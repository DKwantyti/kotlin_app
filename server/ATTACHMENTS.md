# Проверка передачи вложений

## Причина и исправление

`File is empty` воспроизведён регрессионным тестом корректного multipart-запроса. Это ошибка серверной обработки, а не требование создать файл другим способом и не проблема выбора файла в Android.

1. Раньше `readUpload` сохранял ссылку на поток файла и продолжал обход multipart. К моменту последующего чтения данные части могли уже быть сброшены. Теперь файл читается до перехода к следующей части в ограниченный по размеру временный файл. Это поддерживает поля подписи после файла и не требует держать до 1 ГБ в памяти. Временный файл удаляется после обработки, в том числе при ошибке. Членство в беседе проверяется до чтения файла; прежние проверки имени, расширения и размера сохранены.
2. При скачивании входной поток закрывался вокруг вызова `respondOutputStream`, до выполнения отложенного писателя ответа. Теперь поток закрывается внутри писателя после копирования. На настоящем файловом хранилище прежний код возвращал пустое содержимое; ByteArrayInputStream в старых тестах скрывал ошибку, поскольку его закрытие ничего не делает.

Схема базы, правила ролей, удаления и Android-код загрузки/скачивания не менялись. Серверное исправление хранится самостоятельным коммитом и требует обновления сервера команды, чтобы работать за пределами локальной демонстрации.

## Регрессионные тесты

`AttachmentRouteTest` использует настоящий `LocalFileStorage` в отдельной временной папке и тестовый Ktor-сервер:

- TXT с Unicode, CRLF и объёмом больше одного буфера: загрузка, подпись после файловой части, размер, скачивание и побайтовое сравнение.
- Бинарный PNG: такая же полная цепочка и сравнение байтов.

Оба теста падали до исправления: PNG при загрузке с `File is empty`, TXT при сравнении скачанных данных — 0 байтов вместо 176128. После исправления оба проходят.

```powershell
.\gradlew.bat :server:test --tests '*AttachmentRouteTest'
```

## Проверка Android-приложения

В эмуляторе API 37 файлы выбраны системным выбором файлов по кнопке вложения. Использована только отдельная локальная база `unimessenger_ui_demo` на PostgreSQL `127.0.0.1:55439`, API `18080`, без данных команды.

Оба вложения скачаны нажатием на файл в беседе. Приложение сохраняет скачанное в свой кэш. Для проверки копии извлечены через `adb exec-out run-as com.university.messenger cat cache/<имя>`; отдельный HTTP-клиент вместо скачивания приложением не использовался.

| Файл | Размер | Побайтовое сравнение | SHA-256 оригинала и скачанной копии |
| --- | ---: | --- | --- |
| `uni-transfer-check.txt` | 72 байта | Совпали | `96caf3cfac6e46a89896dd062fcc732c586d5930162fa4a4fe506f11621860ae` |
| `uni-transfer-check.png` | 292 байта, 64×64 | Совпали | `4ec4f9e3e2803570da3ba5da51aca24167c03ca21f759b55bd4956905b4a0222` |

Обязательные `:domain:test :server:test :app:assembleDebug` прошли. Всего 29 тестов, без ошибок и пропусков, включая PostgreSQL-интеграцию. `:app:lintDebug` прошёл: 0 ошибок, 17 предупреждений.

Проверены небольшие TXT и PNG; ручная проверка около 1 ГБ, нестабильной сети и внешних облачных провайдеров файлов не выполнялась. Временная буферизация требует свободного места на диске сервера дополнительно к постоянному хранилищу на время загрузки. Android-приложение остаётся на Kotlin (12 исходных `.kt`), с 7 XML-макетами и View Binding; перехода на другой стек нет, требование Java/Kotlin соблюдено.
